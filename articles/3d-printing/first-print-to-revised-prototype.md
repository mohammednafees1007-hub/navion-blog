# From First Print to Better Prototype: Recording Useful Feedback

A first prototype is useful when it answers a clear question. Does the board fit inside the enclosure? Can you reach the connector? Is the display readable from the intended position? Decide what you will check before requesting the print.

## Separate observations from guesses

Record what you can actually see or measure. “The lid cannot close because it touches the connector” is more useful than “the model is wrong.” Add a photograph or marked drawing that identifies the problem area.

Keep the approved model version and your original requirements with the notes. That gives the next discussion a clear starting point and helps prevent a revised request from accidentally using an older file.

## Make a small change list

For each issue, write the part name, observed problem and intended change. Where possible, give the relevant measurement and units. If you are uncertain how to fix it, explain the result you need rather than prescribing an arbitrary adjustment.

An example entry might read: “Lid v1: USB cable cannot connect with the lid fitted. Please review the opening using the attached connector dimensions.” This is an illustrative scenario, not a record of a NAVION customer project.

## Agree what the next version will check

If several changes interact, ask whether a partial sample would answer the main question before another full print. Confirm the revised file, cost and timing. Do not assume that redesign or repeat printing is included in the original quotation.

When the new version arrives, repeat the relevant checks and record the result. A fit that looks correct is different from a part that has been tested during actual operation. Keep those conclusions separate in your project notes.

[Discuss a revised print](https://shop.navionrobotics.com/3d-printing) with NAVION 3D using your versioned files and observations. Clear feedback makes the next request easier to understand.
